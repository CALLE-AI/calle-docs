For this preview, install the TypeScript or Python SDK from its local checkout.
These packages have not been published. The [registry packages](/legacy-sdks)
continue to serve existing call-task integrations.

These local checkouts also include the [unreleased response additions](/calls#preview-availability).
The wait helpers below require a deployment that returns `result_status`;
do not use them against the September 22 test contract, which lacks that field.
Use the [REST Quickstart](/quickstart#wait-for-the-result) for that contract.

## Install from a local checkout

Run these from a separate test project, adjusting the paths to your local checkouts.
The TypeScript checkout must be built before linking it:

```bash
pnpm --dir /path/to/server-sdk-typescript install --frozen-lockfile
pnpm --dir /path/to/server-sdk-typescript run build
pnpm add /path/to/server-sdk-typescript
```

For Python 3.11 or later, use an isolated environment:

```bash
python3 -m venv .venv
.venv/bin/pip install /path/to/server-sdk-python
```

You can also install the local `.tgz` or `.whl` produced by those checkouts.

## Test environment

```bash
export CALLE_BASE_URL="https://test-api.heycall-e.com"
export CALLE_API_KEY="<YOUR_TEST_API_KEY>"
export CALLE_TEST_PHONE="<AUTHORIZED_E164_PHONE>"
export CALLE_IDEMPOTENCY_KEY="hello-test-001"
```

The examples omit `region` and `locale` and ask for English in the task.
You may supply either hint explicitly; a phone/region conflict returns
`422 input_incomplete`. Keep the original input unchanged on retries.
The examples below create a real call when run with valid credentials and a number.

## TypeScript

```ts
import { CalleClient } from "@call-e/calle";

const client = new CalleClient({
  apiKey: process.env.CALLE_API_KEY!,
  baseUrl: process.env.CALLE_BASE_URL!,
});

const created = await client.calls.create(
  {
    task: "Say hello in English, allow a brief reply, then politely end the call.",
    phone: process.env.CALLE_TEST_PHONE!,
    resultSchema: {
      type: "object",
      additionalProperties: false,
      properties: { summary: { type: "string" } },
      required: ["summary"],
    },
  },
  { idempotencyKey: process.env.CALLE_IDEMPOTENCY_KEY! },
);
console.log("Keep this Call ID:", created.id);

const ready = await client.calls.waitForResult(created.id, {
  intervalMs: 2000,
  timeoutMs: 600000,
});
console.log(ready.result, ready.error);
console.log(ready.transcript);
```

## Python

```python
import os
from calle import CalleClient

client = CalleClient(
    api_key=os.environ["CALLE_API_KEY"],
    base_url=os.environ["CALLE_BASE_URL"],
)
created = client.calls.create(
    task="Say hello in English, allow a brief reply, then politely end the call.",
    phone=os.environ["CALLE_TEST_PHONE"],
    idempotency_key=os.environ["CALLE_IDEMPOTENCY_KEY"],
    result_schema={
        "type": "object",
        "additionalProperties": False,
        "properties": {"summary": {"type": "string"}},
        "required": ["summary"],
    },
)
print("Keep this Call ID:", created["id"])
ready = client.calls.wait_for_result(
    created["id"], interval_seconds=2, timeout_seconds=600
)
print(ready["result"], ready["error"])
print(ready["transcript"])
```

The client defaults to the production base URL if you omit the override, so pass
the test URL explicitly. Wait helpers stop when `result_status` is not `pending`;
a timeout does not cancel or replace the Call.

## Retry safely

Persist one key and the original request before calling `create`. Retrying the
same logical call uses both unchanged. Do not generate a new key inside a retry
loop or copy resolved `region/locale` from the response into an originally
omitted input. A replay returns the original Call even after failure or completion;
it does not initiate another phone call. Follow [Call retry decisions](/calls#idempotency)
to distinguish `409 idempotency_conflict` with reason `creation_in_progress`
from changed-input conflicts.

## Existing integrations

Keep a legacy client for historical call-task IDs. The current SDK's Calls
methods use the single-target interface; Goal methods retain their existing contract.
HTTP/Python use `result_schema` and `error.detail_code`; TypeScript uses
`resultSchema` and `error.detailCode`. See the [migration guide](/migration).
